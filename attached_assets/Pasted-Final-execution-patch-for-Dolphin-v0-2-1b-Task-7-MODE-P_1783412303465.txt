==================================================
1. ADD EXPLICIT MANIFEST WRITE STEP — BLOCKING
==================================================

The documented sequencing says:

normalize
→ validate
→ write manifests
→ publish

but the current end-to-end command chain says:

verify
→ extract-metadata
→ extract-raw
→ normalize
→ validate
→ publish

This is inconsistent because publish requires:

pipeline-manifest.public.json

and that manifest must only be created after successful validation.

Add an explicit script:

scripts/nautical/write-manifests.sh

Exact pipeline order:

1. verify-checksums.sh
2. extract-metadata.sh
3. extract-raw.sh
4. normalize.sh
5. validate.sh
6. write-manifests.sh
7. publish.sh

Requirements for write-manifests.sh:

- abort unless the immediately preceding/current pipeline outputs have passed validation
- write pipeline-manifest.json
- write pipeline-manifest.public.json
- public validation.status must be "PASS"
- set validatedAt only at this stage
- never write PASS manifests after failed validation
- publish.sh must abort if the public manifest is absent

Prefer recording a pipelineRunId so validation and manifests can be tied to the same generated output set.

==================================================
