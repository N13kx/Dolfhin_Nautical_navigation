==================================================
2. SOUNDING DEPTH DENSITY
==================================================

Current behavior is insufficient:

MapLibre collision alone does not guarantee that substantially more
depth labels become visible as the user zooms in.

Target user behavior:

- far zoom:
  sparse representative charted-depth labels

- medium zoom:
  visibly more labels

- normal boating zoom:
  substantially more labels

- close zoom:
  high-detail portrayal with most/all non-overlapping relevant soundings visible

Only features with:

chartedValueRelationToDatum === "below"

may be rendered as normal charted-depth labels.

Do not portray "above" or "at" as normal water-depth labels.

The stored signed chartedValueMetres value must remain unchanged.

Do not modify normalized GeoJSON.

==================================================
3. DETERMINISTIC PROGRESSIVE DENSITY
==================================================

Do not rely solely on text-size + collision for density.

Implement deterministic zoom-dependent label density.

Requirements:

- same source data + viewport + zoom gives stable results
- no random sampling
- no flickering caused by random feature selection
- density clearly increases as zoom increases
- MapLibre collision still prevents excessive overlaps

A suitable approach may use deterministic properties already present
on the feature (for example pipelineFeatureId / stable feature ordering)
to select progressively larger subsets at lower zooms.

Do not fabricate nautical values.

Do not change pipelineFeatureId semantics.

At the highest practical Family Alpha zoom level, do not unnecessarily
suppress valid below-datum soundings except for label collision.

Document the chosen thresholds and selection strategy.

6. OFFICIAL NAVIGATION MARK PORTRAYAL
==================================================

Improve the currently generic circle portrayal so official navigation
marks are clearly visible and distinguishable on the Dolphin map.

This is prototype Family Alpha portrayal.

Requirements:

- use only verified properties present in the normalized data
- do not invent port/starboard semantics when the required attribute is absent
- do not claim IHO S-52 compliance
- preserve sourceKind: official
- do not combine with OpenSeaMap
- do not move official features
- do not alter provenance

Prefer simple recognizable MapLibre vector shapes/symbols using existing
data and no new external dependency unless absolutely necessary.

If the data contains sufficient verified attributes to safely distinguish
relevant buoy/beacon categories, use them.

If an attribute is ambiguous or unavailable:
use a neutral official-mark symbol rather than inventing nautical meaning.

Lights may be portrayed distinctly but must not imply characteristics
that are not present in the data.
